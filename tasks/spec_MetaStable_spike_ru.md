# noUSD — краткая спека (RU)

Краткая версия `spec_MetaStable_spike.md`. Статус: спайк, только дизайн. Реализация — отдельный слой,
аудит отдельно. Это шаг в сторону стейблкоина, а не финальная форма.

## Суть
noUSD — стейблкоин, обеспеченный стейбл-LP-позициями в `StableLPManager`. Залог — ликвидность в
стейбл-парах (близко к $1), которая при этом продолжает зарабатывать комиссии V4.

## Роли
- **Минтер** — держатель LP-позиции (владелец `StableLPManager`). Лочит залог, минтит noUSD, комиссии с
  залоченной ликвидности оставляет себе. Это и есть стимул минтить.
- **Холдер** — пользуется noUSD. В v1 не может погасить его on-chain, выходит через рынок.

## Механика
- Один сейф на менеджер: счётчик `debt` (сминчено noUSD), залог = все позиции по par. Без per-position
  учёта. Минт — на сумму всех позиций.
- Минт: контроллер оценивает суммарный залог 1:1, минтит noUSD и ставит `debt`.
- Вывод **частичный**: `withdrawTo` можно, пока остаток залога (par) ≥ `debt`. Сжёг X noUSD → `debt`
  упал → выводишь X. Сжёг половину → вывел половину. Не всё-или-ничего.
- `allocate`/`reinvest`/`claimFees` работают всегда (добавлять и собирать комиссии можно).
- Залог не уходит, пока не покрыт `debt` → выпущенный noUSD всегда обеспечен.
- Оценку остатка при выводе делает либо менеджер on-chain (par-сумма по позициям), либо контроллер
  (оценил + подтвердил сжигание → авторизовал вывод). Склоняемся к контроллеру — менеджер легче.

## Структура (3 части, в репо садится только третья)
1. noUSD ERC-20 — минт/бёрн только через контроллер.
2. Контроллер + реестр залога — допускает менеджеры (governance), держит минт 1:1, лимиты на стейбл и
   breaker, маршрутизирует минт/бёрн.
3. Хук в менеджере: `lockAuthority` + `debt` + guard «залог ≥ debt» в `withdrawTo`. Иммутабельные клоны → это
   v2-менеджер; влезает при `optimizer_runs=200` (≈917 B запаса). Текущие v1-клоны — через эскроу (бэклог).

## Оценка / минт
Минт 1:1: noUSD выпускается на par-стоимость залога (принципал позиции, каждый стейбл = $1). Полное
обеспечение, без хейрката и без LTV-дисконта. Оракул нужен только для breaker (можно ли минтить против
этого стейбла), а не для расчёта суммы. По par, а не по цене пула — чтобы цену нельзя было накрутить на
минте.

## Пег
Soft. Снизу держит минтер: чтобы разлочить залог, ему надо выкупить и сжечь noUSD. Сверху — если noUSD
дороже обеспечения, выгодно минтить. Кодом пег не гарантирован.

## Депег залогового стейбла
Если стейбл падает (например DAI → $0.80), LP-позиция через арбитраж превращается почти целиком в плохой
токен. Залог по факту дешевле выпущенного против него noUSD. Так как токен общий и ликвидаций нет,
минтеры с хорошим залогом первыми выкупают подешевевший noUSD и забирают свой хороший залог — остаётся
noUSD на битом активе (run). Это главный системный риск.

Меры (лёгкие):
- Оракул на каждый стейбл + circuit-breaker: при отклонении стоп минта против этого залога.
- Лимит на стейбл (не больше Y% обеспечения). Хейрката нет — минт 1:1, единственная подушка это буфер.
- Буфер из 10% протокольной комиссии — гасит малый бэд-дебт.
- Whitelist: при депеге governance делистит стейбл → его стоимость в учёте списывается до oracle-цены →
  минтерам даётся окно на ребаланс позиции в нормальный стейбл / частичное сжигание noUSD → остаток
  покрывается буфером, что сверх — списывается. При восстановлении стейбла — релист.

Ликвидаций нет (by design). Сильный депег сверх буфера всё равно частично роняет noUSD — это принятый
хвостовой риск.

## Решено
- Model A: soft-peg, owner-only разлок, без force-redeem холдера.
- Общий протокольный noUSD + governance-реестр залога.
- Минтер оставляет комиссии.
- Минт 1:1 (полное обеспечение, без хейрката/LTV).
- Депег: лёгкая позиция (breaker + лимиты + буфер + whitelist), без ликвидаций.
- Один сейф: `debt` + частичный вывод (сжёг часть → вывел часть, залог ≥ debt). Не per-position, не
  всё-или-ничего. Закладка — в v2-менеджере (runs≤400 вмещает); v1-клоны через эскроу (бэклог).

## Открыто (параметры)
Источник оракула и порог отклонения, лимиты на стейбл, доля и размер буфера, критерии whitelist.
