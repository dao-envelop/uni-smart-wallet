# task_046 — Unichain: сделать включение операторского контура одношаговым и явным

**Ветка:** `task/046-unichain-operator-wiring`
**Находка:** `qa-workspace/quality/findings/2026-08-11-unichain-operator-loop-cannot-act.md` (S3)
**Затрагивает:** `script/oracle_feeds.json`, `script/README.md`; правка `quality/metrics.md` — на
стороне `qa-workspace`

## Симптом

Менеджер `uni-stable` (`0x9f7E19B7A3fe5e767C515203446eb9A99A104970`, Unichain 130) числится под
оператором и держит открытую позицию, но ни одна операторская операция там не пройдёт. Причин три, и
они независимы — то есть «включить оператора» не сводится к переводу флага `execute` в `true`, как
сейчас выглядит.

Задача не в том, чтобы включить сеть (это решение владельца), а в том, чтобы включение перестало
быть неявным набором ручных шагов.

## Доказательство

**1. Оракул не привязан к менеджеру.**

```
get_manager_config 130 0x9f7E19B7A3fe5e767C515203446eb9A99A104970
→ "priceOracle": "0x0000000000000000000000000000000000000000"
oracle_status 130 …
→ { "wired": false, "maxDeviationBps": null }
```

`BaseLPManager.sol:348-349` — `if (o == address(0)) revert OperatorSwapGuardRequired();`, то есть
безусловный реверт, а не деградация.

**2. Оракул на сети есть, но фида под вторую валюту пары в нём нет.**

`deployments/130.json` → `"oracle": "0xAC7966454B32006de29273094Ff0FCf8D367eF87"`. У контракта четыре
события `FeedSet` (2026-07-25), все с `heartbeat` 86400: агрегаторы `0xbd1cD1518e…` (USDC),
`0xC13f3E31…` (BTC), `0xBcE70e19…` (ETH), `0xdAd6f904…` (UNI).

```bash
curl -sS "https://unichain.blockscout.com/api/v2/addresses/0xAC7966454B32006de29273094Ff0FCf8D367eF87/logs"
```

Управляемые валюты менеджера — USDC `0x078D782b760474a361dDA0AF3839290b0EF57AD6` и **USD₮0**
`0x9151434b16b9763660705744891fA906F660EcC5`. В `script/oracle_feeds.json` секция `130` содержит
только `BTC / ETH / USDC / UNI / LINK` — записи под USDT/USD₮0 **нет**. Значит и после
`setPriceOracle` своп USDC↔USD₮0 упрётся в «нет референса» для второй ноги.

**3. Газа на этой сети нет.**

```
get_status → chainId 130: "execute": false, balance { "eth": "0", "estimatedOps": 0 },
             managers[0].authorized = true
```

Состояние позиции при этом здоровое: диапазон `[-89, 111]`, текущий тик ≈ **+8**, позиция в
диапазоне; идл 0.14 USDC + 0.19 USD₮0 против ~9.6 USD в позиции.

## Корень (гипотеза)

Unichain разворачивали до появления оракул-гейта (task_031/032, аудит 2026-07-18). Пост-деплойный
шаг «привязать оракул к менеджеру и залить фиды под его валюты» существует только как ручное
действие: на Arbitrum его выполнили 2026-07-25 (`SetOracleFeeds.s.sol` + `setPriceOracle`), на
Unichain — залили фиды, но не привязали оракул. В `script/README.md` этого шага нет вовсе, поэтому
пропуск ничем не ловится.

Отсутствие USD₮0 в `oracle_feeds.json` — того же происхождения: файл собирали под BTC/ETH/USDC/UNI, а
стабильный менеджер на Unichain торгует пару, которой в нём нет.

## Что делать

1. **`script/oracle_feeds.json`, секция `130`** — добавить запись для USD₮0
   (`0x9151434b16b9763660705744891fA906F660EcC5`, 6 decimals), если Chainlink публикует для неё
   USD-фид на Unichain. Если не публикует — записать это в `_note` секции как известное ограничение
   сети, вместе со следствием: стабильные пары с USD₮0 на Unichain не могут иметь операторских
   свопов. Пустое место в файле сейчас читается как «забыли», а не как «нельзя».
2. **`script/README.md`** — оформить пост-деплойный шаг явным пунктом: после `CreateManager` вызвать
   `setPriceOracle` (owner-only, `onlyOwnerNFT`) и убедиться, что фиды залиты под **все** управляемые
   валюты менеджера, а не только под популярные токены сети. Указать, что без этого шага любой
   операторский своп ревертит `OperatorSwapGuardRequired`.
3. Рассмотреть проверку в `SetOracleFeeds.s.sol`: пройти по управляемым валютам менеджера и
   предупредить (`console2.log`) о тех, для которых в файле нет записи. Это дешевле, чем ловить
   пропуск на проде, и ровно та ошибка, которая здесь произошла.

**Чего не делать в этой задаче:** не вызывать `setPriceOracle` на боевом менеджере и не пополнять
газом — это операции владельца и продуктовое решение, задача их только подготавливает.

## Как проверить

Если сеть решено включать:

```
oracle_status 130 0x9f7E19B7A3fe5e767C515203446eb9A99A104970
```

→ `wired: true` с ненулевым `maxDeviationBps`; `propose_allocate` с пресвопом собирает план, а не
отдаёт `OperatorSwapGuardRequired`.

Если сеть остаётся выключенной — проверка в документации: `script/README.md` содержит шаг привязки
оракула, `oracle_feeds.json` содержит либо запись USD₮0, либо `_note` о том, почему её нет, а
`SetOracleFeeds.s.sol` печатает предупреждение о валютах без фида (проверяется прогоном
`--rpc-url $UNICHAIN_RPC` без `--broadcast`).

`forge fmt --check` — правки в JSON, Markdown и скрипте; `forge build --sizes` не двигается.
