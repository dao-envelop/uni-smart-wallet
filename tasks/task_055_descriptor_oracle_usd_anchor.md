# task_055 — дескриптор печатает $259,66 там, где $99,25: наивный «$1 за токен» стал основным путём

**Репозиторий:** `uniswap-smart-wallet` · **Ветка:** `task/055-descriptor-oracle-usd`
**Снимает предпосылку:** `tasks/task_041_descriptor_pool_price_valuation.md` («no on-chain USD anchor
otherwise», «honest limitation without an oracle»)
**Заведена:** 2026-09-29, по жалобе на страницу менеджера

## Симптом

Волатильный менеджер `0x0dc6d808edf2a57c14ddaef56ecdf3949ce5be26` (Arbitrum, «AutoBot», `eVolLP`)
рисует в NFT-карточке стоимость в **2,6 раза** выше реальной. Раскодированный `tokenURI(1)`:

```
attributes: Open Positions 1 | Total Value (USD) 259.66 | Est. APR (bps) 3960
SVG:        AutoBot · Open positions: 1 · Total value · $259.66 · ~APR: 39.59% · ETH · ARB
```

Реально в менеджере ~$99. Одна открытая позиция: пул **ETH/ARB 0,3 %**, тики `87960…99960`,
`L = 7 467 860 503 445 321 315`, пул на тике 95062 (13 437 ARB за ETH).

| | Количество | Chainlink (ETH $2697,19 / ARB $0,2008) | «$1 за токен» |
|---|---|---|---|
| позиция, ETH | 0,013990966 | $37,74 | $0,01 |
| позиция, ARB | 258,761939 | **$51,95** | **$258,76** |
| невыбранные комиссии | — | ~$0,3 | ~$0,88 |
| idle ARB / ETH | 6,866116981 / 0,003034673 | $1,38 / $8,19 | $6,87 / $0,00 |
| **итого** | | **$99,25** (позиции $89,69) | **$259,66** ← карточка |

Вся разница — 258,76 ARB, посчитанные по $1 вместо $0,2008.

## Корень

`src/WalletPositionDescriptor.sol:123-148`, `_positionUsd`. USD-якорь один — стейбл в паре:

```solidity
if (isStable[currency1])      { /* token1 = $1, token0 по цене пула */ }
else if (isStable[currency0]) { /* наоборот */ }
else {
    // No stable anchor → naive $1/token fallback.
    principalUsd = a0 * USD / unit0 + a1 * USD / unit1;   // ← ARB = $1
    feeUsd       = f0 * USD / unit0 + f1 * USD / unit1;
}
```

`isStable` — аллоулист, зашитый в конструктор при деплое (USDC/USDT/DAI). В паре ETH/ARB стейбла нет
ни с одной стороны → третья ветка.

## Почему это задача, а не известное ограничение

`task_041` оставила эту ветку сознательно и даже закрепила тестом («Add a no-stable-pair case
asserting the naive fallback still applies»). Ограничение было честным при трёх условиях, и все три
с тех пор перестали выполняться:

1. **«Нет on-chain якоря»** — есть. Менеджер публично отдаёт `priceOracle()`; у этого он равен
   `0x4F59E6454462C9d3851D4B4126DC200FE6209e2D` (`task_027`, `task_045`), и нужные фиды **уже
   засеяны** — прочитано с прода:

   | Валюта | Агрегатор | heartbeat | feed dec | token dec |
   |---|---|---|---|---|
   | ARB | `0xb2A824043730FE05F3DA2efaFa1CBbe83fa548D6` | 87 300 | 8 | 18 |
   | ETH (native) | `0x639Fe6ab55C921f74e7fac1ee960C0B6293ba612` | 2 655 | 8 | 18 |
   | USDC | `0x50834F3163758fcC1Df9973b6e91f0F0F0434aD3` | 765 | 8 | 6 |
   | USD₮0 | `0x3f3f5dF88dC9F13eac63DF89EC16ef6e7E25DdE7` | 765 | 8 | 6 |

2. **Пары без стейбла были углом, стали нормой.** На момент `task_041` волатильный продукт держал
   ETH/USDC и WBTC/USDC — там якорь есть всегда. У этого менеджера пара без стейбла — **единственная
   открытая позиция**, то есть наивная ветка считает весь портфель.
3. **Число стало публичным за пределами картинки.** `stablelp-ui/src/lib/server/managerMeta.ts:37`
   читает атрибут `Total Value (USD)`, а `opengraph-image.tsx` подписывает его «Total value» — ссылка
   на менеджер в мессенджере показывает $260. Плюс миниатюра в `ManagerCard` и любой кошелёк или
   маркетплейс, который отрисует NFT. На момент `task_041` соцкарточки не существовало.

Отдельно: `~APR: 39.59%` считается из `feeUsd/principalUsd` в тех же фиктивных единицах. Это
приблизительно ARB-взвешенное отношение, а не USD-доходность; после правки пересчитается само, но
проверить стоит.

## Что делать

**Порядок якорей в `_positionUsd`: оракул → стейбл-пара → отказ.**

1. **Новый источник.** Дескриптор получает `wallet`, значит может прочитать
   `BaseLPManager(payable(wallet)).priceOracle()`. У `ChainlinkPriceOracle` публичны `feeds(Currency)`
   и `feedBounds(Currency)`, поэтому дескриптор читает агрегатор/heartbeat/decimals сам и дергает
   `latestRoundData()`, **повторяя правила свежести `_read`** (`src/oracle/ChainlinkPriceOracle.sol:427-448`):
   неположительный ответ, нулевой/будущий `updatedAt`, старше heartbeat, упор в `minAnswer`/`maxAnswer`
   → «нет мнения».

   > `_read` — `internal`, публичного getter'а нет. **Не добавлять его в оракул**: новая версия оракула
   > = пересев всех фидов на всех сетях, боль из `task_050`. Дублирование чтения в дескрипторе дешевле
   > и не трогает контракт, от которого зависят операторские гейты.

2. **Обе ноги через оракул, когда фиды есть на обе.** Это снимает и вторую неточность: сейчас даже в
   стейбл-ветке волатильная нога конвертируется по **цене пула**, то есть карточка наследует любой
   перекос пула относительно рынка (у этого пула ETH/USD₮0, например, расхождение с фидами доходило до
   106 bps — см. `stablelp-ui/tasks/task_133`).

3. **Фолбэки в этом порядке.** Нет `priceOracle` (ноль) или нет фида на одну ногу → текущая
   стейбл-якорная логика по цене пула. Нет и стейбла → **не печатать число**: атрибут
   `Total Value (USD)` опустить, в SVG вывести `—` (и не считать APR). Наивный $1 убрать полностью.
   Это тот же принцип, который фронт принял в `stablelp-ui/task_078`: «a number the reader will act on
   has to be one we can stand behind». Сейчас on-chain-число — единственное место, где $1-par остался.

4. **Подпись.** Дескриптор считает только позиции, без idle (так задумано в `task_041`). После правки
   карточка покажет ≈$89,7, а хиро приложения ≈$98 — две разные величины, и подпись в SVG стоит
   уточнить («Positions value»), иначе следующий вопрос будет про эти $8.

5. **EIP-170.** Дескриптор — обычный контракт, не клон; на `task_041` было ≈18 224 B при запасе ~6,3 КБ.
   Перемерить `forge build --sizes` после правки.

## Как проверить

- `forge fmt --check`, `forge test -vvv`, `forge build --sizes`.
- Тесты в `test/WalletPositionDescriptor.t.sol`: **заменить** кейс «no-stable-pair → naive fallback» на
  «no-stable-pair + оба фида в оракуле → oracle-взвешенная сумма» и добавить «no-stable-pair без фида →
  атрибут отсутствует / `—`». Мок-агрегаторы в репозитории есть (`test/` для оракульных задач).
- Живая сверка: раскодировать `tokenURI(1)` у `0x0dc6d808edf2a57c14ddaef56ecdf3949ce5be26` до и после
  репойнта. Ожидание: `$259.66` → **≈$89,7**; перекрёстная проверка через `UniLens.managerFull`

## Раскатка

Новый деплой менеджеров **не нужен** — дескриптор подменяемый:

1. задеплоить новый `WalletPositionDescriptor` на 1 / 130 / 8453 / 42161 (`script/DeployStableLP.s.sol`,
   `deploy.descriptor: true`);
2. `node scripts/sync-deployments.mjs` в `stablelp-ui` — фронт подхватит адрес и покажет
   `DescriptorNotice` («Descriptor update available», `src/components/manager/DescriptorNotice.tsx`);
3. владелец каждого затронутого менеджера репойнтит `setPositionDescriptor` (`onlyOwnerNFT`, средства не
   двигаются, `useSetDescriptor`);
4. новые клоны получают актуальный дескриптор при `initialize` из фабрики.

Приоритет раскатки — волатильные менеджеры с парами без стейбла: у них наивная ветка считает весь
портфель.

## Что вне этой задачи

- Включать idle в число на NFT — отдельное решение; `task_041` исключила его сознательно.
- Публичный getter USD в оракуле (см. выше — не делать в этой задаче).
- Перекос пула относительно фидов как таковой — операционная тема,
  `stablelp-ui/tasks/task_133_min_liquidity_leverage.md`.

Выводы:

* **Модель подтверждена на всех 7**: реконструкция совпадает с атрибутом до цента. Других причин
  расхождения нет.
* **Там, где у всех позиций есть стейбл-нога, NFT верен** (`0x3d53`, `0xA3d8`: 9.29 = 9.29,
  97.94 ≈ 97.93).
* **Ошибка идёт в обе стороны**, не только «завышает». Нога-«дешёвый токен» (ARB, UNI, PENDLE, LINK)
  по $1 завышает, нога ETH/WBTC по $1 занижает почти до нуля. `0x7C77` на Unichain печатает **$0.00**
  при $6.16 в позициях; `0xCD30` и `0x1159` занижены в 2–3 раза; `0x0DC6` и `0xd07E` завышены.
  5 из 7 менеджеров с позициями показывают неверное число.
* **NFT и хиро UI — разные величины даже при верных ценах.** NFT = принципал + **невыбранные
  комиссии**, только открытые позиции, **без idle**. Хиро UI = принципал **без комиссий** + **idle**
  (`useManagerView.ts:44-45`: `idleUsd + positionsTvl`, обе по одному `priceGet` — API, затем спот
  пула). У `0xA3d8` при верных ценах: 97.94 против 107.36, разница = idle 9.57 − комиссии ~0.15.
  Поэтому п.4 («Positions value» в подписи SVG) обязателен, иначе расхождение с хиро останется
  у каждого менеджера с idle.
* Попутно для фронта: idle ETHFI у `0xd07E` не имеет цены в `/api/prices/42161` — хиро это помечает
  «≥» (task_078), в пересчёте выше он не учтён.
