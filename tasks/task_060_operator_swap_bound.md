# task_060 — объём операторского свопа ограничен средствами менеджера, круг запрещён

**Репозиторий:** `uniswap-smart-wallet` · **Ветка:** `task/060-operator-swap-bound`
(от master `8ed3e29`, релиз v2.2.0, **до деплоя**) · **Продукты:** Stable, Volatile, Open ·
**Severity:** HIGH (аудит 2026-10-20, operator round-trip drain)

## Симптом

Скомпрометированный или недобросовестный оператор за **одну** операцию уводит заметную долю менеджера, и
при этом каждая проверка оракула проходит.

PoC (`test/OperatorSwapBound.t.sol`). Менеджер держит 10e18 + 10e18 (≈ $20), пул 0.3 %, реальный
`ChainlinkPriceOracle(100, 50, 10)`:

1. Бот кладёт JIT-ликвидность `L = 1e24` в `[-60, 60]` того же пула (флэш-капитал).
2. Бот вызывает `moveLiquidity(SALT, liq, add, bridge)`: мост 1000e18 X→Y, затем пресвоп ноги `add`
   995.5e18 Y→X в том же пуле.
3. Бот забирает JIT-ликвидность.

| | Менеджер | Бот |
|---|---|---|
| v2.2 (master 8ed3e29), move с мостом, A = 1000e18 | 20e18 → **14.0e18** (−30 %) | +5.99e18 |
| **прод v2.1.0** (`12bcb45`), две ноги `allocate`, A = 700e18 | 20e18 → **15.8e18** | +4.19e18 |

Повторяется в каждой транзакции (одна операторская операция на tx), пока менеджер не опустеет. Стороннему
адресу без роли атака недоступна, владельцу не нужна.

## Причина

- Оракул проверяет **каждый своп отдельно**: `amountOut ≥ (1 − θ)·fair`, θ = 100 bps. Своп с потерей
  только комиссии пула (~99.55 % от fair при 0.3 %) проходит.
- `_settleManaged` рассчитывает **чистую** дельту один раз в конце `unlock`. Внутри операции дельта
  может уходить в минус, поэтому номинал свопа ничем не ограничен средствами менеджера.
- Два встречных свопа номиналом A стоят менеджеру ≈ 2·fee·A из его баланса. Эту комиссию получают LP
  пула в текущем тике, а при JIT это почти целиком оператор.

Принятый остаток аудита 04.09 (θ − fee за операцию) молча предполагал, что объём ограничен средствами
менеджера. Множитель A/holdings ≈ 50× это допущение снимает.

## Что сделано

Общий `BaseLPManager._boundOperatorSwap(key, zeroForOne)`. Он вызывается из `_guardSwap` (Stable:
`_preSwap` в allocate и reinvest) и из `_guardOp` (Volatile/Open: `_guardedSwap`, то есть пресвопы
allocate, recenter, мост и `add` у move) только для оператора (`o != 0`) и только для свопа
(`amountIn != 0`; spot-проверки add не затронуты). Владелец ограничений не получает.

1. **Объём ≤ средств.** После свопа `currencyDelta(in) + balanceOfSelf(in) ≥ 0`, иначе
   `OperatorSwapExceedsHoldings(Currency c)`. Ликвидность, снятая в той же операции (move, recenter), —
   это кредит в дельте, поэтому она учитывается как средства менеджера.
2. **Нельзя выкупить проданное.** Каждый своп помечает входную валюту как проданную (transient-слот с
   ключом = адрес валюты). Если валюта выхода уже помечена — `OperatorSwapRoundTrip(Currency c)`.
   Это закрывает прямой круг X→Y→X и любой цикл через другие валюты (X→Y→Z→X), а не только пару.
   Цепочки (мост E→U, затем пресвоп U→T у `add`) и повторы в одну сторону разрешены. Метка живёт
   транзакцию, а для оператора это ровно одна операция (`_requireAuthorized`, одна оп на tx).

Пары `(in, out)` (исходный вариант правила 2) не хватало: при трёх и более валютах в пулах менеджера
оставался треугольник. Правило по валюте строже и при этом дешевле на 31 B.

## Остаточный риск после фикса

- За одну операцию оператор продаёт валюту не больше, чем она есть у менеджера, и цикл невозможен.
  Поэтому суммарный номинал ≤ (k − 1)·V, где k — число валют на пути цепочки, V — стоимость
  менеджера. На практике (пул на две валюты, Stable — всегда через USDT) номинал ≤ V.
- Потеря за операцию ≤ θ·номинал. В PoC-конфигурации (V = $20, θ = 1 %, fee 0.3 %): ≤ $0.20
  вместо $6. Из этого JIT-оператор получает комиссию ≈ $0.06, остальное — проскальзывание в пределах θ.
- **Не закрыто:** оборот между транзакциями. Можно сделать X→Y в одной tx и Y→X в следующей, и каждая
  по-прежнему платит комиссию JIT-оператору. Это отдельное решение (cooldown или лимит оборота за
  период); здесь не делалось.
- v2.1 (прод, неапгрейдимые клоны) не исправить. Единственная мера — выдавать роль оператора только
  доверенным ключам.

## Новые ошибки (ABI)

```solidity
error OperatorSwapExceedsHoldings(Currency c); // продано больше, чем есть (баланс + кредит unlock)
error OperatorSwapRoundTrip(Currency c);        // выкуп валюты, проданной ранее в той же операции
```

Фронт и MCP должны их декодировать (`sync-abi`). Для MCP это ответ «разбей на отдельные транзакции» или
«уменьши объём».
