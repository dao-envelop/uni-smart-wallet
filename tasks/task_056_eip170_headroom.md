# task_056 — бюджет EIP-170: освободить место без изменения интерфейса

**Репозиторий:** `uniswap-smart-wallet` · **Ветка:** `task/056-eip170-headroom`
(от `task/055-descriptor-oracle-usd`; релиз v2.2.0, за ней стекаются task_057 и task_058)

## Симптом

Релиз v2.2.0 должен принести в менеджеры оракул при создании (task_057) и пресвоп в другом пуле при
`moveLiquidity` (task_058). Места под это не было:

| Контракт | Runtime, B | Свободно до 24 576 |
|---|---|---|
| StableLPManager | 24 114 | 462 |
| VolatileLPManager | 24 468 | 108 |
| OpenVolatileLPManager | 24 530 | **46** |

(`forge build --sizes` на `task/055-descriptor-oracle-usd`, forge 1.8.1, solc 0.8.26, runs 200.)

Одна новая перегрузка внешней функции с декодером структуры стоит сотни байт; у Open их нет.

## Причина

Не один большой кусок, а набор повторов: CBOR-метаданные в хвосте каждого байткода, одиннадцать
инлайновых `emit MetadataUpdate` (32-байтный топик на каждом), OZ `Address` ради одного эскейп-хэтча,
предварительные проверки вне `unlock`, которые внутри `unlock` всё равно повторяются, две копии
пресвопа у Stable, побайтовый цикл в `name()`, повторное чтение `ownerOf` после `onlyAuthorized`.

декодируют ошибки по селекторам). Все тесты, которые были, проходят без правок.

### Подробности, которые стоит знать

**Шаг 1 — отменён.** Без CBOR-трейлера (IPFS-хэш метаданных + версия solc) байткод на 53 B короче,
но верификация становится хрупкой: Etherscan сходится только при сборке ровно с этим `foundry.toml`,
а Sourcify без хэша метаданных даёт лишь частичное совпадение — сканеры показали бы контракт как
не до конца верифицированный. 53 B не стоят риска для того, что видят пользователи в эксплорерах;
трейлер оставлен, `deployments/*.json` поле `cborMetadata` не получает.

**Шаг 3.** Отказались от `Address.sendValue`/`functionCallWithValue`. Что потеряно — только проверка
`AddressEmptyCode`: calldata, отправленная на адрес без кода, теперь проходит как no-op. Это может
сделать только владелец и только себе во вред. Пустой revert у вызываемого теперь даёт пустой revert
(раньше `FailedCall()`); непустой (кастомная ошибка цели) пробрасывается как и раньше. Для нативной
отправки `results[i]` теперь — то, что вернул получатель (у EOA пусто, как и было).

**Шаг 4.** `PoolManager.unlock` не оборачивает ошибки колбэка, поэтому `UnknownPool` изнутри
`unlock` доходит до вызывающего тем же селектором с теми же аргументами. `_pullLiquidity` теперь сам
бросает `UnknownPosition` (в т. ч. при нулевом pull по пустому salt — как раньше делала пред-проверка
`withdrawTo`) и `DeltaExceedsLiquidity`. Побочный эффект для `moveLiquidity`: неизвестный `fromSalt`
теперь даёт `UnknownPosition`, а не `UnknownPool(0)` — точнее, чем было.

**Шаг 6a — форма имеет значение.** Первый вариант (локальная `bool byOwner = _requireAuthorized();` в
теле) дал Stable −169, а Volatile **+129**: локальная переменная, удерживаемая через `abi.encode`
calldata-структуры, раздувает перетасовку стека. Вызов прямо в аргументе `abi.encode(...)` (он первый,
`abi.encode` вычисляет аргументы слева направо — авторизация по-прежнему идёт первой) вернул байты.
Чтобы проверки не обогнали авторизацию, `UnknownPosition` у `recenter`, `ZeroLiquidity` у
`moveLiquidity` и `NoLegs` у Volatile `allocate` переехали в обработчики внутри `unlock` — посторонний
по-прежнему получает `NotAuthorized` раньше любой другой ошибки (тест на это есть). Модификатор
`onlyAuthorized` остался у `claimFees`.

**`tokenURI` try/catch (+20 B).** Дескриптор обходит все позиции и читает метаданные токенов —
может кончиться газ или попасться токен с кривым `symbol()`. Раньше revert дескриптора ломал
`tokenURI`, а с ним и карточку менеджера во всех кошельках/маркетплейсах, пока владелец не сменит
дескриптор. Теперь — та же деградация, что и без дескриптора: `""`. Не ловится только успешный ответ,
который не декодируется как строка. Касается только менеджеров на новых имплементациях.

## Тесты

`test/Task056Headroom.t.sol` (16 тестов) фиксирует наблюдаемое поведение каждого переписанного пути:
reverting / gas-burning / рабочий дескриптор; `name()` на 32 байтах и с мусором после первого нуля
(сырой ABI-ответ канонически дополнен нулями); пачка — проброс кастомной ошибки цели, результаты
вызовов, нативная отправка, отказ нативной отправки; `UnknownPool` у allocate / allocateFrom /
reinvest после переезда проверки внутрь `unlock`; `UnknownPosition` / `DeltaExceedsLiquidity` у
`withdrawTo`; посторонний получает `NotAuthorized` раньше `NoLegs`/`UnknownPosition`/`ZeroLiquidity`;
ошибки владельца прежние.

Прогон: `forge fmt --check && forge build --sizes && forge test -vvv` — 343 passed, 0 failed,
4 skipped (форк-тесты без RPC).

## Что это значит для фронта и деплоя

- ABI не изменился: ни селекторов, ни ошибок, ни событий. `npm run sync-abi` не обязателен ради этой
  задачи (понадобится ради task_057/058).
- Новые имплементации получат новые адреса (другой байткод) — это часть общего деплоя v2.2.0.
